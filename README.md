# Task Manager API

## Overview

The Task Manager API is a RESTful API built with Node.js and Express.js. It supports creating, retrieving, updating, and deleting tasks, along with input validation, error handling, filtering, sorting, and priority-based retrieval.

Each task has the following fields:

- `id`: Unique numeric identifier.
- `title`: Required, non-empty string.
- `description`: Required, non-empty string.
- `completed`: Required boolean (`true` or `false`).
- `priority`: Required value: `low`, `medium`, or `high`.
- `createdAt`: Creation timestamp generated by the server when a task is created.

## Technologies

- Node.js
- Express.js
- JavaScript
- JSON file for initial task data
- Postman or curl for API testing

## Setup Instructions

### Prerequisites

Install [Node.js](https://nodejs.org/) and npm. Use [Postman](https://www.postman.com/) or curl to test the endpoints.

### 1. Open the project folder

Open the `task-manager` folder in a terminal or in VS Code.

### 2. Install dependencies

```bash
npm install
```

If Express is not listed in the project's dependencies, install it with:

```bash
npm install express
```

### 3. Configure `task.json`

Create a `task.json` file in the same folder as `app.js`. Example:

```json
{
  "tasks": [
    {
      "id": 1,
      "title": "Learn Node.js",
      "description": "Practise Express APIs",
      "completed": false,
      "priority": "high",
      "createdAt": "2026-10-09T10:00:00.000Z"
    },
    {
      "id": 2,
      "title": "Learn Angular",
      "description": "Build a frontend",
      "completed": true,
      "priority": "medium",
      "createdAt": "2026-10-10T10:00:00.000Z"
    }
  ]
}
```

Keep your own task records if you already have them. Ensure every task includes a valid `priority` and a `createdAt` value for the optional features to work as expected.

### 4. Start the server

```bash
node app.js
```

By default, the API runs on port `3000`.

Base URL:

```text
http://localhost:3000
```

The port can be overridden using the `PORT` environment variable. If you use a `.env` file, make sure the app loads it with `require('dotenv').config()` and that `dotenv` is installed.

## API Endpoints

All examples below use `http://localhost:3000` as the base URL.

### 1. Get all tasks

**Method:** `GET`  
**Path:** `/tasks`

Returns all tasks.

```http
GET http://localhost:3000/tasks
```

**Success:** `200 OK` — returns an array of tasks.

### 2. Get a task by ID

**Method:** `GET`  
**Path:** `/tasks/:id`

Returns one task by its numeric ID.

```http
GET http://localhost:3000/tasks/1
```

**Success:** `200 OK` — returns the matching task.  
**Error:** `404 Not Found` if the task does not exist.

```json
{
  "message": "Task not found"
}
```

### 3. Create a task

**Method:** `POST`  
**Path:** `/tasks`

Creates a task. In Postman, choose **Body → raw → JSON**.

```json
{
  "title": "Learn Express.js",
  "description": "Practise REST APIs",
  "completed": false,
  "priority": "high"
}
```

The server generates the ID and `createdAt` timestamp.

**Success:** `201 Created` — returns the created task.  
**Error:** `400 Bad Request` if required fields are missing or invalid.

Validation rules:
- `title` must be a non-empty string.
- `description` must be a non-empty string.
- `completed` must be a boolean.
- `priority` must be `low`, `medium`, or `high`.

### 4. Update a task

**Method:** `PUT`  
**Path:** `/tasks/:id`

Updates an existing task. In Postman, choose **Body → raw → JSON**.

```http
PUT http://localhost:3000/tasks/1
```

Example body:

```json
{
  "title": "Learn Node.js",
  "description": "Practise Express and REST APIs",
  "completed": true,
  "priority": "medium"
}
```

Send all required fields in the request body.

**Success:** `200 OK` — returns the updated task.  
**Errors:**
- `400 Bad Request` — invalid task data.
- `404 Not Found` — task ID does not exist.

The original `createdAt` timestamp is retained when a task is updated.

### 5. Delete a task

**Method:** `DELETE`  
**Path:** `/tasks/:id`

Deletes a task by ID.

```http
DELETE http://localhost:3000/tasks/1
```

**Success:** `200 OK`

```json
{
  "message": "Task deleted successfully"
}
```

**Error:** `404 Not Found` if the task does not exist.

### 6. Filter tasks by completion status

**Method:** `GET`  
**Path:** `/tasks?completed=true` or `/tasks?completed=false`

Get completed tasks:

```http
GET http://localhost:3000/tasks?completed=true
```

Get incomplete tasks:

```http
GET http://localhost:3000/tasks?completed=false
```

**Success:** `200 OK` — returns only tasks matching the requested status.  
**Error:** `400 Bad Request` if `completed` is not `true` or `false`.

### 7. Sort tasks by creation date

**Method:** `GET`  
**Path:** `/tasks?sort=asc` or `/tasks?sort=desc`

Oldest tasks first:

```http
GET http://localhost:3000/tasks?sort=asc
```

Newest tasks first:

```http
GET http://localhost:3000/tasks?sort=desc
```

**Success:** `200 OK`.  
**Error:** `400 Bad Request` if `sort` is not `asc` or `desc`.

Tasks without a `createdAt` value are treated as having a timestamp of `0` by the current implementation. Add valid timestamps to existing tasks for meaningful sorting.

Filtering and sorting can be combined:

```http
GET http://localhost:3000/tasks?completed=false&sort=desc
```

### 8. Get tasks by priority

**Method:** `GET`  
**Path:** `/tasks/priority/:level`

Supported levels are `low`, `medium`, and `high`.

Examples:

```http
GET http://localhost:3000/tasks/priority/high
GET http://localhost:3000/tasks/priority/medium
GET http://localhost:3000/tasks/priority/low
```

**Success:** `200 OK` — returns tasks matching the requested priority. An empty array is returned if no tasks match.  
**Error:** `400 Bad Request` for an unsupported priority level.

```json
{
  "message": "Priority must be low, medium, or high"
}
```

## Testing with Postman

1. Start the server with `node app.js`.
2. Open Postman and create a new HTTP request.
3. Select the method (`GET`, `POST`, `PUT`, or `DELETE`).
4. Enter the request URL from the endpoint documentation.
5. For `POST` and `PUT`, select **Body → raw → JSON** and enter the example request body.
6. Click **Send**.
7. Check the HTTP status code and JSON response.

### Suggested test checklist

- `GET /tasks` returns the task list.
- `GET /tasks/1` returns a task; a nonexistent ID returns `404`.
- A valid `POST /tasks` returns `201`.
- A POST with an empty title, empty description, incorrect `completed` type, or invalid priority returns `400`.
- A valid `PUT /tasks/1` updates the task; an invalid body returns `400`.
- `DELETE /tasks/1` removes the task from the current in-memory list.
- `GET /tasks?completed=true` and `GET /tasks?completed=false` return the expected subsets.
- `GET /tasks?sort=asc` and `GET /tasks?sort=desc` return tasks in the requested order.
- `GET /tasks/priority/high` returns high-priority tasks.
- Invalid `sort`, `completed`, or priority values return `400`.

## Testing with curl

Examples for a terminal with curl installed:

Get all tasks:

```bash
curl http://localhost:3000/tasks
```

Create a task:

```bash
curl -X POST http://localhost:3000/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Learn Express.js","description":"Practise APIs","completed":false,"priority":"high"}'
```

Update a task:

```bash
curl -X PUT http://localhost:3000/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"title":"Learn Node.js","description":"Practise APIs","completed":true,"priority":"medium"}'
```

Filter incomplete tasks:

```bash
curl "http://localhost:3000/tasks?completed=false"
```

Sort newest first:

```bash
curl "http://localhost:3000/tasks?sort=desc"
```

Get high-priority tasks:

```bash
curl http://localhost:3000/tasks/priority/high
```

Delete a task:

```bash
curl -X DELETE http://localhost:3000/tasks/1
```

## Error Handling

| Status code | Meaning |
| --- | --- |
| `200 OK` | Request completed successfully. |
| `201 Created` | A task was created successfully. |
| `400 Bad Request` | Request input or query parameter is invalid. |
| `404 Not Found` | The requested task ID does not exist. |

## Data Persistence Note

The app reads initial tasks from `task.json` when it starts, but task changes are kept in memory. New tasks and updates are not written back to `task.json`. Restarting the server reloads the original file contents. Persistent storage can be implemented as a future improvement.
